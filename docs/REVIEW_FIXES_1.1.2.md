# 1.1.2 审查整改与验证

日期：2026-10-01。依据用户提供的《插件代码审查-1.1.1.md》核对源码后整改，保留原有通用 MDX/MDD 读取方式、用户路径选择和单一内置 Speex 安装包。

## 修复对应关系

| 审查发现 | 1.1.2 修改 | 回归证据 |
| --- | --- | --- |
| LZO 精确长度下错误扩容 | `match_next` 按实际复制长度 `t` 判断扩容，保留边界检查 | 1/2/3 字节尾部、精确 8 字节公开 MDX 查询、截断与过小限额 |
| 别名归一化误判循环 | 用记录偏移识别访问身份，每条分支独立维护祖先集合，保留 20 层限制 | 标点/大小写合法跳转、真循环、分支共享记录 |
| 扫描失败丢失原词典 | 全部扫描成功后提交 folder/list/path；失败只更新提示 | 不可访问目录保留原索引、有效空目录清空、直接选文件失败保留状态 |
| 外置来源报错阻断回退 | 来源错误记录具体路径并继续其他目录/MDD，失效定位撤销，取消单独传播 | stat 错误、缓存读取失败、失效分卷、关闭及 AbortError |
| 连续 Speex 流绕过 30 秒 | 累计所有逻辑流的采样时长，在头部、解码中和裁剪后检查 | 2 秒双流正常、两个 30 秒流被拒绝，其他格式/CRC/取消检查 |
| 普通音频重复读取 | 已读字节直接生成 URL，并发读取合并 | 首次 MP3 只读一次，audio/普通资源共享 URL 与 I/O |
| MDD 未命中重复遍历 | 有界定位和缺失缓存、读取/解压/耗时统计，保留排序回退 | Unicode/跨块/重复偏移、50 块排序回退及重复未命中缓存、缓存淘汰 |
| 资源设置重建 MDX 索引 | 分开 MDX 与资源代次，更新资源只失效资源 | 资源配置与恢复自动关联保留当前 MDX 索引 |

资源异步读取完成后复查取消状态；清理缓存时增加代次，防止过期请求重新填入。没有移除 MDD 的兼容扫描，也没有一次性载入整个资源包。

## 自动化结果

`npm test`：**33/33 通过，0 失败、0 跳过**。用例数据由项目自行生成，不含用户词典和音频。

除上表外，覆盖 CSS 相对路径/导入条件/背景图片/备用字体、HTML 基础过滤、关闭后 URL 撤销、划选词组/断行连字符/长度限制、批注整份数据复制和菜单回调清理。

Speex 测试实际执行附带 WASM：窄带单声道与连续流，三种模式的双声道/每包三帧输出，损坏 CRC、取消和累计时长。宽带/超宽带测试使用合法窄带 null 子模式及缺省扩展层；并非所有实际音质模式的完整样本覆盖。

本地 `npm run build`、`npm run pack:source` 产出 1.1.2 XPI 和源码 ZIP。GitHub CI 另行执行相同单元测试与构建。

## 复现隔离验证

先构建，在一个明确指定的全新目录准备配置：

```powershell
npm ci --ignore-scripts
npm test
npm run build
node scripts/prepare-zotero-verification.mjs "自己的全新验证目录"
```

脚本生成自制 PDF、数据目录、配置和只在测试副本中加载的验证插件。若目标已有 `data/zotero.sqlite`，脚本拒绝覆盖。手动以 Zotero 的 `-no-remote -profile "验证目录\profile"` 启动；Windows 后台启动时使用 `Start-Process -WindowStyle Hidden`。结果写入验证目录中的 `report.json`，测试实例完成后退出。测试入口确认数据目录与指定目录相同，且没有预设词典路径。不要将测试插件装到正常配置中。
